💵 AWS pricing models — pick the shape

ModelBest forTrade-off
On-DemandSpiky, unpredictable, short-livedHighest unit cost
Savings Plans (Compute)Steady baseline across EC2/Fargate/Lambda1- or 3-year commit
Reserved InstancesRDS, Redshift, ElastiCache (instance-class lock)Less flexible than SP
SpotBatch, dev, fault-tolerant fleets, Fargate SpotCan be interrupted with 2 min notice
Default playbook: Compute Savings Plan for steady baseline + On-Demand for headroom + Spot for everything that can tolerate interruption. Three knobs cover most fleets.
Compute Savings Plans replaced most use cases for Convertible RIs — they cover EC2, Fargate, Lambda. RIs are still right for managed databases.

⚙️ Compute right-sizing

Compute Optimizer

  • Free service, opt-in per account
  • Recommends EC2, ASG, Lambda, EBS sizes
  • Reads 14 days of CloudWatch data
  • Tells you "you're paying for x, you need y"

Graviton2 / Graviton3

  • ARM-based EC2 / Fargate / RDS / ElastiCache
  • ~20% cheaper, often better perf-per-watt
  • Container images: build multi-arch once
  • Try Fargate Spot for non-critical tiers
Compute Optimizer is the cheapest 20% you can save without thinking. Graviton is the next 20% if your stack supports it — most modern languages do.

💾 Storage & data transfer

S3

  • Lifecycle → Glacier / Deep Archive
  • Intelligent-Tiering for unknown patterns
  • Delete incomplete multipart uploads

EBS

  • gp3 over gp2 — cheaper + tunable IOPS
  • Snapshot lifecycle policies
  • Delete unattached volumes

Network

  • VPC endpoints for S3 / DDB — kills NAT cost
  • CloudFront for egress to internet
  • Watch cross-AZ chatter
The hidden line item: NAT Gateway egress for traffic that should be going through a VPC endpoint. Audit it — the savings are usually four-figure monthly.
VPC endpoints are the single most under-used cost lever. NAT Gateway processing fees add up fast on chatty fleets.

📊 Database cost levers

Aurora

  • Aurora Serverless v2 — capacity scales with load
  • Aurora pause/resume for dev (Serverless v1)
  • Reader scaling separate from writer

DynamoDB

  • On-Demand for unpredictable traffic
  • Provisioned + Auto Scaling for steady
  • TTL to prune old items
Match the billing mode to the load shape, not to what's familiar. On-Demand DynamoDB is cheaper than provisioned if traffic is genuinely spiky.
Aurora Serverless v2 finally scales fast enough for production OLTP — v1 had cold-start issues that pushed teams off it. Worth re-evaluating if they tried it years ago.

🏷️ Tagging & FinOps culture

Tagging is the load-bearing principle

Without consistent tags, every cost report is "EC2 in us-east-1" — useless for accountability. Activate cost allocation tags in the billing console (one-way switch) and enforce via SCPs or AWS Config.

Minimum tag set

  • Owner — person or team
  • Environment — prod / staging / dev
  • CostCenter — chargeback target
  • Application — logical workload

FinOps habits

  • Weekly cost review with engineering
  • Show-back / charge-back per team
  • Anomaly alerts to a Slack channel
  • Quarterly Savings Plan true-up
"Analyze and attribute" from the Well-Architected Cost pillar — tagging is how you operationalize it. Tag enforcement is where most teams give up; SCPs make it durable.
