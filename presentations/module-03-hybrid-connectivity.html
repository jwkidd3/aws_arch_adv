🧩 Why hybrid (still)?

The cloud rarely arrives all at once

Active Directory in the data center. Mainframes. Latency-bound trading systems. Regulated data with sovereignty constraints. Hybrid is the default for years — not the exception.

Migration in flight

Lift-and-shift workloads talking back to on-prem dependencies during the move.

Steady-state hybrid

Identity, file shares, ERP, plant-floor systems that won't move.

Burst & DR

On-prem primary, AWS as elastic capacity or DR target.

The honest answer: most "lift and shift" stops being lift-and-shift the moment a dependency on-prem can't move. Plan for the link, not the cutover.

🔒 AWS Site-to-Site VPN

What it is

  • IPSec tunnels over the public internet
  • Two tunnels per connection (different AWS endpoints) for redundancy
  • Static routes or dynamic via BGP
  • Terminate on a VGW or a Transit Gateway

When to choose it

  • You need encrypted connectivity today, not in 6 weeks
  • Bandwidth needs < ~1 Gbps and latency tolerance is real
  • Pair with Direct Connect as encrypted overlay or DR path
  • FIPS 140-2 endpoints available in GovCloud and select commercial regions
Cost shape: hourly per tunnel + standard egress. Cheap to start, predictable to run.
Both tunnels should be configured on the customer device — learners are surprised that AWS provisions two endpoints by default. ECMP load-balancing only works on the TGW side.

📱 AWS Client VPN

What it is

  • Managed OpenVPN-based remote-access service
  • Mutual cert auth, AD auth, or SAML/Identity Center
  • Per-connection authorization rules
  • Reaches into one or many VPCs (and via TGW, on-prem)

When to choose it

  • Operators need shell access to private resources
  • You want to retire a self-hosted VPN appliance
  • Workforce is remote and identity-first
  • Pair with split-tunnel for performance
Cost shape: per-endpoint-hour + per-active-connection-hour. Watch idle endpoints — the per-endpoint hourly charge runs whether anyone is connected or not.
For ad-hoc admin sessions, SSM Session Manager often beats Client VPN on cost and audit trail. Reserve Client VPN for users who need IP-routed access (RDP, custom protocols).

⚡ AWS Direct Connect

What it is

  • Private fiber from your network to an AWS DX location
  • 1, 10, or 100 Gbps dedicated; sub-1G hosted via partners
  • Virtual interfaces: Private VIF, Public VIF, Transit VIF
  • BGP-only routing — no static

When to choose it

  • Sustained > 1 Gbps or strict latency requirements
  • Predictable per-port cost beats egress on bursty workloads
  • Compliance requires the traffic stay off the public internet
  • Pair with VPN for encrypted overlay (DX is unencrypted by default)
Lead time: physical cross-connect provisioning is weeks-to-months. Order DX before the migration plan needs it, not after.
DX is not encrypted at L2 — if your auditor cares, run a VPN over DX (it works and is the standard pattern). Direct Connect Gateway is Module 5; we keep it light here.

🔄 BGP, redundancy, and failover

BGP fundamentals

ASN per side, advertise prefixes, AWS prefers more-specific routes; AS-path prepending biases inbound traffic.

Active/active

Two DX connections in different DX locations — ECMP across them on the AWS side via TGW.

VPN as backup

Site-to-Site VPN as a tertiary path; AS-path-prepend it so it's only used on DX failure.

BGP hygiene: bidirectional forwarding detection (BFD) on both DX and VPN cuts failover from minutes to seconds.
Most "the failover didn't work" stories are missing BFD or have an MED/AS-path quirk that no one tested. Encourage a quarterly failover test, scheduled on a Tuesday morning, not Friday at 5 PM.

📧 Hybrid DNS with Route 53 Resolver

Two endpoints, two directions

By default, on-prem DNS can't resolve *.compute.amazonaws.com private records, and AWS resolvers can't reach corp.example.com. Resolver endpoints fix both directions.

Inbound endpoint

  • ENIs in your VPC that on-prem can target
  • On-prem DNS forwards *.aws.example.com to these IPs
  • Resolves private hosted zones in AWS

Outbound endpoint + rules

  • ENIs that forward queries from VPC to on-prem resolvers
  • Conditional forwarding rules per zone (e.g., corp.example.com → on-prem DNS IPs)
  • Share rules across accounts via RAM
This is the #1 hybrid networking gotcha. Walk the inbound vs outbound diagram on the whiteboard if you can — learners conflate them every single class. The lab makes them configure both.

🛡️ Compliance & FIPS 140-2

FIPS endpoints

  • FIPS 140-2 validated cryptographic modules required for US Federal workloads
  • Site-to-Site VPN exposes FIPS endpoints in select commercial regions and across GovCloud
  • Pin clients to vpn-endpoint.region.amazonaws.com FIPS variant

Encryption-in-transit checklist

  • VPN: IPSec by definition
  • DX: not encrypted — overlay VPN if required
  • Resolver traffic: DoH / DoT to inbound endpoints in supported regions
  • TLS for any application protocol regardless of link
If you have federal learners, this slide gets attention. For commercial workloads, mention FIPS as an option but don't get sucked into compliance theater — encryption hygiene matters more day-to-day.

🔧 Lab 3: Site-to-Site VPN + Route 53 Resolver

Stand up an encrypted hybrid link end-to-end

  • Provision a Customer Gateway and Site-to-Site VPN connection terminating on a VGW (or TGW), pointed at the pre-staged on-prem-simulator VPC
  • Configure both IPSec tunnels with BGP; verify both come up and routes propagate to your VPC route table
  • Create a Route 53 Resolver inbound endpoint in your VPC and an outbound endpoint with a conditional forwarding rule for the simulator's zone
  • Test name resolution in both directions (dig from EC2 to on-prem, from simulator to AWS); validate via VPC Flow Logs and tunnel CloudWatch metrics
Duration: ~65 minutes · Tunnels: 3–5 min to negotiate · Pre-req: instructor-staged simulator VPC
Tunnel negotiation has a hard floor — budget for it. While tunnels come up, have learners read the BGP route advertisements in the customer config bundle. Cleanup: VPN + endpoints first, then VGW.
