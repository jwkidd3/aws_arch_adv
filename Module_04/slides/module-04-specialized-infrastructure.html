🧩 When the standard region isn't enough

Three reasons to leave the region behind

Latency — the speed of light is real. Sovereignty — data must stay on premises. Bulk movement — petabytes don't fit through a 1 Gbps pipe in a reasonable time.

Push compute out

Outposts, Local Zones, Wavelength — AWS hardware closer to your users or your factory floor.

Pull data in

Snow Family, Storage Gateway, DataSync — staged or streamed bulk transfer.

Pick the right silicon

GPU, HPC, FPGA, Inferentia / Trainium — specialized instance families that earn their cost.

Frame the choice as "buy the right tool, not the closest tool." A standard m-family in us-east-1 is the default; everything in this module is what you reach for when the default fails the workload.

🏠 AWS Outposts

What it is

  • AWS-managed racks (or 1U/2U servers) installed in your data center
  • Same APIs and services as the parent region (EC2, EBS, S3 on Outposts, RDS, ECS/EKS)
  • Connected back to the parent region for control plane & updates
  • Dedicated capacity — you size and order it

When to choose it

  • Single-digit-millisecond latency to on-prem systems
  • Data residency that forbids the cloud
  • Manufacturing / healthcare / banking with specific compliance constraints
  • Need for AWS-consistent tooling, on-prem
Reality check: Outposts is a multi-year financial commitment and a physical install. Recommend it only when the alternative is "we can't move at all."
Most learners will never deploy Outposts. They should still recognize it as the answer when latency or sovereignty rules out a region. Mention 1U/2U Outposts servers for smaller-footprint use cases.

📱 Local Zones & Wavelength

Local Zones

  • AWS infrastructure in metro areas without a full region
  • Subset of services (EC2, EBS, ELB, RDS, others)
  • Single-digit-millisecond latency to nearby end users
  • Use for media, gaming, real-time rendering, virtual desktops

Wavelength

  • AWS compute embedded in 5G carrier networks
  • Single-digit-millisecond latency from mobile devices
  • Use for vehicle telemetry, AR/VR, live broadcasting
  • Reach via the carrier's 5G network, not the public internet
Mental model: Local Zone = "AWS in your city". Wavelength = "AWS inside the cell tower". Both extend a parent region's VPC.
Both are subset-of-services edges. If a workload needs DynamoDB or Lambda specifically, those usually live in the parent region — design accordingly. Latency benefit is real but you trade service breadth.

❄️ AWS Snow Family

Snowcone

~8 lbs, 8 TB usable, edge compute + DataSync agent built in. Field-deployable.

Snowball Edge

~50 lbs, up to ~80 TB (Storage Optimized) or compute-heavy variants with GPUs.

Snowmobile

A 45-foot shipping container holding up to 100 PB. Yes, really. Niche but real.

Decision rule: if your transfer would take longer than ~1 week over your available bandwidth, ship a Snow device instead. Calculate against egress cost too.
Snow devices arrive encrypted with KMS keys you control. Tracking is via the Snow console — learners are surprised by how operationally similar it feels to ordering an EBS volume.

💾 AWS Storage Gateway

Three modes

  • File Gateway — NFS / SMB on-prem, S3 in the back
  • Volume Gateway — iSCSI block, cached or stored modes; snapshots to EBS
  • Tape Gateway — VTL interface for legacy backup software, S3 / Glacier in the back

How to deploy

  • VM appliance (VMware / Hyper-V / KVM) or hardware appliance
  • Local cache for hot data, async upload to AWS
  • Encryption in transit and at rest by default
  • CloudWatch metrics for cache utilization & throughput
Tape Gateway is the surprise win — it lets backup admins keep their existing software (NetBackup, Veeam) and quietly retire physical tape. File Gateway is the most common in fresh deployments.

📥 AWS DataSync

What it does

  • High-throughput managed transfer for files & objects
  • On-prem agent (NFS/SMB/HDFS) or AWS-to-AWS (S3/EFS/FSx)
  • Incremental, parallelized, with integrity verification
  • Scheduled or one-shot tasks; CloudWatch metrics & logs

vs. Storage Gateway

  • DataSync is movement: copy / sync / migrate
  • Storage Gateway is continuous access: a hybrid filesystem
  • DataSync over DX or VPN; can also use VPC endpoint
  • Pair them: gateway for steady-state, DataSync for the bulk seed
Combo move: DataSync seeds the initial petabyte; Storage Gateway handles the ongoing read/write traffic from existing on-prem applications.
DataSync's bandwidth throttling and scheduling are under-appreciated — you can run nightly transfers without saturating the corporate uplink. Module 13 revisits DataSync for migration workloads.

🚀 HPC and GPU instances

HPC families

Hpc6id, Hpc7g: tightly-coupled MPI workloads. Pair with cluster placement groups + Elastic Fabric Adapter (EFA) + FSx for Lustre.

GPU families

G4, G5, P4, P5: ML training & inference, gaming, rendering. Inferentia / Trainium for cost-optimized ML.

Where they shine

Genomics, CFD, seismic, ML training, graphics rendering, video encoding — workloads where the right silicon eclipses any architectural cleverness.

EFA bypasses the OS kernel for MPI traffic — sub-microsecond latency between cluster nodes. Without it, HPC instances are just expensive general-purpose compute.
Mention SageMaker briefly — for ML, learners often reach for SageMaker before hand-rolling on EC2. Module 11 covers application-tier scale; this slide is purely "right silicon for the workload."

✅ Module recap

Edge family: Outposts (full region in your DC), Local Zones (metro), Wavelength (carrier 5G). All extend a parent region's VPC.
Bulk data: Snow for offline ship-it transfer; DataSync for managed online sync; Storage Gateway for continuous hybrid access. Combine seeds and steady-state.
Right silicon wins: EFA + FSx Lustre + cluster placement groups for HPC; G/P families for GPU; Inferentia / Trainium for cost-optimized ML.

🔧 Lab 4: Storage Gateway + DataSync

Move bulk data in once, then keep it flowing

  • Deploy a File Gateway VM (or use the provided pre-staged appliance) and create an SMB/NFS file share backed by an S3 bucket in your prefix
  • Mount the share from a learner EC2 instance; write a few files; verify they appear in S3
  • Configure a DataSync task from a source location (provided EFS or NFS dataset) to a destination S3 bucket; run the task and inspect transfer metrics in CloudWatch
  • Compare the two: gateway = continuous access; DataSync = one-shot or scheduled bulk move; terraform destroy when done
Duration: ~50 minutes · Pre-req: instructor-staged File Gateway appliance · End of Day 1
If the appliance pre-stage failed, fall back to DataSync-only and walk Storage Gateway via the console screenshots. Cleanup is critical — gateway resources can linger and incur charges.
