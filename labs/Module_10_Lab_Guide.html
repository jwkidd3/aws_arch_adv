Advanced Architecting on AWS

Lab 10 — Build a data lake (S3 + Glue + Athena)

Objective

Stand up a minimal data lake by hand: drop CSV files into S3, run a Glue Crawler to infer the schema, query with Athena. The point is the pattern — separating storage (S3) from catalog (Glue) from compute (Athena).

Time budget: 35 minutes

Throughout this lab, replace <you> with your student slug. If your slug contains a hyphen (e.g., mary-smith), use the underscore form (mary_smith) only where this guide explicitly calls for <you_underscore> — Glue databases reject hyphens.

Pre-flight

  1. Sign in to Sandbox<N> via IAM Identity Center. Confirm role badge top-right reads AWSAdministratorAccess @ Sandbox<N>.
  2. Region: US East (N. Virginia) us-east-1.
  3. Open CloudShell.

Steps

1. Create bucket and seed three CSVs (4 min)

In CloudShell, set your slug then run the block:

YOU=<you>                       # e.g. mary-smith (hyphen ok here)
YOU_DB=$(echo $YOU | tr '-' '_')   # underscored form for Glue DB
LAKE=archadv-$YOU-datalake

aws s3 mb s3://$LAKE --region us-east-1
aws s3api put-public-access-block --bucket $LAKE \
  --public-access-block-configuration "BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true"

cat > /tmp/sales1.csv <<'EOF'
order_id,region,product,quantity,revenue
1001,us-east,widget-a,3,29.97
1002,us-east,widget-b,1,49.99
1003,us-west,widget-a,5,49.95
1004,eu-west,widget-c,2,79.98
1005,ap-south,widget-b,4,199.96
EOF

cat > /tmp/sales2.csv <<'EOF'
order_id,region,product,quantity,revenue
2001,us-east,widget-a,7,69.93
2002,us-west,widget-c,3,119.97
2003,us-west,widget-b,2,99.98
2004,eu-west,widget-a,4,39.96
2005,ap-south,widget-c,1,39.99
EOF

# Both files go to the SAME unpartitioned prefix s3://$LAKE/sales/
aws s3 cp /tmp/sales1.csv s3://$LAKE/sales/sales1.csv
aws s3 cp /tmp/sales2.csv s3://$LAKE/sales/sales2.csv
aws s3 ls s3://$LAKE/sales/

Expected: aws s3 ls lists exactly two files. Failure mode: BucketAlreadyOwnedByYou or BucketAlreadyExists — pick a different slug or re-use the existing bucket name.

2. Create the Glue database (1 min)

  • Navigate: AWS Glue → Data Catalog → Databases → Add database.
  • Name: archadv_<you_underscore>_db (e.g., archadv_mary_smith_db). No hyphens. Glue silently rejects them with an obscure error.
  • Leave Location and Description empty. Click Create database.

3. Create the Glue IAM role (3 min)

  • Navigate: IAM → Roles → Create role.
  • Trusted entity type: AWS service. Service: Glue. Next.
  • Permissions policies: tick AWSGlueServiceRole. Next.
  • Role name: archadv-<you>-glue-role. Create role.
  • Open the role you just made → Permissions → Add permissions → Create inline policy → JSON, paste:
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:ListBucket"],
      "Resource": [
        "arn:aws:s3:::archadv-<you>-datalake",
        "arn:aws:s3:::archadv-<you>-datalake/*"
      ]
    }
  ]
}
  • Replace <you> in both ARNs with your slug. Policy name: archadv-s3-read. Create policy.

4. Create and run the crawler (6 min)

  • Navigate: AWS Glue → Crawlers → Create crawler.
  • Step 1 — Set crawler properties: name archadv-<you>-sales-crawler. Next.
  • Step 2 — Choose data sources:
    • "Is your data already mapped to Glue tables?" → Not yet
    • Add a data source → S3
    • S3 path: Browse S3 → drill into archadv-<you>-datalake/sales/. (Trailing slash matters — point at the prefix, not the bucket.)
    • Subsequent crawler runs: Crawl all sub-folders (default).
    • Add an S3 data source. Next.
  • Step 3 — Configure security settings: existing IAM role archadv-<you>-glue-role. Next.
  • Step 4 — Set output and scheduling:
    • Target database: archadv_<you_underscore>_db
    • Crawler schedule: On demand
    • Next.
  • Step 5 — Review and create.
  • Back on the crawler list, tick your crawler → Run. Wait ~60–90 sec until status reads Ready and the Last run column shows Succeeded.

Failure modes:

  • Status Failed, log says AccessDenied → the inline S3 policy didn't save or has the wrong bucket name. Re-check Step 3.
  • Status Ready but Tables created: 0 → S3 path was the bucket root, not the sales/ prefix. Edit the crawler and re-run.

5. Verify the catalog (1 min)

  • Navigate: AWS Glue → Data Catalog → Databases → archadv_<you_underscore>_db → Tables in archadv_…_db.
  • You should see one table named sales.
  • Open it. Confirm columns: order_id, region, product, quantity, revenue. There should be no partition keys (by design — we flattened on purpose).

6. Query with Athena (10 min)

  • Navigate: Athena → Query editor.
  • First time only — set the results location. If you see a yellow banner "Before you run your first query, you need to set up a query result location in Amazon S3":
    • Click Edit settings (or Settings → Manage).
    • Location of query result: s3://archadv-<you>-datalake/athena-results/
    • Encryption: leave off. Save.
    • Return to Editor.
  • Left panel: Data source = AwsDataCatalog; Database = archadv_<you_underscore>_db; the sales table should appear below.
  • Paste into the query window and click Run:
SELECT region, SUM(revenue) AS total_revenue
FROM sales
GROUP BY region
ORDER BY total_revenue DESC;

Expected: four rows (ap-south, us-east, us-west, eu-west). Note the Data scanned figure under the run — single-digit KB. That's the Athena pricing dimension.

Failure modes:

  • Table not found: sales → wrong database in the selector or the crawler didn't create the table. Go back to Step 5.
  • Query fails with The S3 location provided to save your query results is invalid → re-do the first-time settings.

7. Drop a third CSV and re-query (3 min)

In CloudShell:

cat > /tmp/sales3.csv <<'EOF'
order_id,region,product,quantity,revenue
3001,us-east,widget-d,10,499.90
3002,ap-south,widget-d,20,999.80
EOF

aws s3 cp /tmp/sales3.csv s3://$LAKE/sales/sales3.csv

You do not need to re-run the crawler — the schema hasn't changed and Athena reads every object under s3://$LAKE/sales/ on each query. Re-run the same Athena query: totals are higher, especially ap-south and us-east. That's the data-lake property — add files, schema unchanged, queries see them.

Validation checklist

Why this matters

You did not provision a database. You did not load through ETL. You dropped files into S3, pointed a catalog at them, and queried with SQL. That is the data-lake pattern — scales from these CSVs to petabytes.

Cleanup

  1. In CloudShell:
aws s3 rm s3://archadv-$YOU-datalake/ --recursive
aws s3 rb s3://archadv-$YOU-datalake
  1. Glue → Crawlers → tick your crawler → Delete.
  2. Glue → Databases → archadv_…_db → Action → Delete database (this also drops the sales table).
  3. IAM → Roles → archadv-<you>-glue-role → Delete.

Stretch goals (only if you finish early)

  • Convert the data to Parquet with a CTAS:
CREATE TABLE sales_parquet
WITH (format = 'PARQUET',
      external_location = 's3://archadv-<you>-datalake/sales-parquet/')
AS SELECT * FROM sales;

Re-run the GROUP BY against sales_parquet. Compare Data scanned. Parquet typically scans 5–20× less on this access pattern.
